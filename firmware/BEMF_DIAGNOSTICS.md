# BEMF: диагностика и калибровка

Актуально для прошивки **0.10**. Описание мотора и API — в
`ARCHITECTURE.md` §11, известные ограничения — в `docs/known_issues.md`.

## Как работает регулирование

- ШИМ 20 кГц, 10 бит, duty `0..1023`; номинальный период управления 10 мс.
- Для измерения оба входа DRV8870 переводятся в LOW, выдерживается 1000 мкс,
  затем ADC1 последовательно читает `BEMF1`, `BEMF2`. Напряжение рельса берётся
  из последней публикации `track` (не старше 100 мс).
- `bEMF = |V(BEMF1) − V(BEMF2)|`; значение фильтруется как
  `filtered = 0.85·filtered + 0.15·bEMF`.
- Измерение выше acceptance ceiling (по умолчанию `0.85·rail`) считается
  недостоверным.
- Дифференциал не выше `rail/64` в течение 100 мс считается отказом датчика,
  если duty ≥ 90 % или цель PID ≥ `rail/16` (здоровый мотор при такой цели уже
  обязан давать заметную ЭДС); сюда же входит «залипание» обоих входов на
  одинаковом ненулевом напряжении. Ниже цели `rail/16` допускается медленное
  ползание, но положительный интегратор ограничен, чтобы отказ датчика не
  вывел duty на средние/высокие значения при малой команде.
- Цель PID — доля текущего rail из калибровочной таблицы. Без валидной таблицы
  используется линейная цель `0.08 + speed/126·(0.90 − 0.08)`.
- Коэффициенты PID задают CV54/55/56. Duty = `base + 0.4·correction`;
  при старте дополнительно действует kickstart CV65.
- При невалидном измерении PID не применяется, PWM не повышается; интегратор и
  предыдущая ошибка сохраняются (история не подменяется нулём). Потеря
  обратной связи дольше 100 мс переводит мост в coast и защёлкивает fault;
  после остановки или калибровки 100-мс окно взводится заново.
- `bemf_use=0` отключает окно выбега и PID при обычном движении. Калибровка и
  `BEMF-COAST` по-прежнему могут открыть окно явно.

## Калибровка

- Запуск из веба: `POST /api/bemf/calibrate`; прогресс — `GET /api/bemf/cal`.
- Запуск по UART: `BEMF-CAL` (мотор должен быть без нагрузки).
- Прогон до 16 точек скорости; результат сохраняется в NVS и применяется к PID.
- `BEMF-CLR` удаляет сохранённую кривую; `BEMF?` читает текущую.
- `BEMF-HDR` печатает готовый заголовок для `bemf_cal_base.h`.
- Ручная запись: `BEMF=<speed>,<frac>,...` (не менее двух пар, значения
  `speed 0..126`, `frac 0..1024`). Точка `speed=0` допустима только с `frac=0`:
  на стоящем моторе ЭДС равна нулю, и ненулевой якорь отвергается.

## UART-команды

| Команда | Назначение |
|---|---|
| `BEMF?` | текущая кривая (count, пары speed/frac) |
| `BEMF-HDR` | C-заголовок с текущей кривой |
| `BEMF-RAW` | rail, BEMF1/2, фильтр, валидность, калибровка, duty, error, integral, corr, pid_ok, target |
| `BEMF-ADC` | сырые значения ADC1: BEMF1, BEMF2, rail |
| `BEMF-COAST` | принудительное окно выбега, значения в мВ |
| `BEMF-TEST <spd> [rev]` | прямой прогон мотора (0..126) |
| `BEMF-CAL` | старт калибровки без нагрузки |
| `BEMF-CLR` | удалить сохранённую кривую |
| `BEMF=<...>` | записать кривую вручную |
| `BEMF-CVSET <cv> <val>` | записать CV через сервисную консоль |

## Веб-API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/api/bemf/cal` | прогресс/параметры калибровки и `use` |
| GET | `/api/bemf/base` | базовая кривая |
| POST | `/api/bemf/calibrate` | старт калибровки; `reset=1` — сброс |
| GET/POST | `/api/bemf/use` | включение/выключение замкнутого контура |

## Практика диагностики

1. Убедиться, что мотор свободен, питание стабильно, `BEMF-ADC` даёт правдоподобные
   значения.
2. Снять `BEMF-RAW` на нескольких скоростях; `pid_ok=0` или `bemf_valid=0`
   указывают на недостоверное измерение/порог.
3. Выполнить `BEMF-CAL` без нагрузки и проверить `BEMF?`.
4. Проверить движение под нагрузкой; при нестабильности — `BEMF-COAST` и
   `BEMF-RAW` для сравнения duty/error/target.
