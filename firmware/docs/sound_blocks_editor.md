# Конструктор звуковых блоков (sound blocks editor)

Единственный редактор звуковой схемы тепловоза — собирается из **готовых
блоков**. Страница написана на ванильном HTML/CSS/JS без фреймворков и внешних
зависимостей; открывается по адресу `/sound-editor/blocks.html`.

- Исходник (правится): `firmware/sound_editor/public/blocks.html`
- Собранная копия (в git): `firmware/sound_editor/dist/blocks.html`
- Пункт в интерфейсе: Настройки → «Конструктор звуков»

## Что сделано

1. **Приложение редактора** — `firmware/sound_editor/public/blocks.html`:
   палитра, холст, инспектор, диагностика, тулбар. Без внешних зависимостей.
   Верхняя панель сгруппирована по функционалу в выпадающие меню (Файл,
   Настройки): в «Файле» — новая схема, импорт/экспорт JSON и
   экспорт блок-схемы картинкой (JPG) или текстом (TXT, логика), в «Настройках» — сетка,
   тема и язык. Кнопки не расползаются на узких экранах; ключевые действия
   («Сохранить», «Выйти») остаются на виду. После меню «Файл» идут три кнопки:
   **T** («Добавить текст», см. «Холст» ниже), **↶** (Отменить) и **↷**
   (Повторить). Копирование/вставка выделенного — блоков и подписей —
   горячими клавишами (`Ctrl+C` / `Ctrl+V`), дублирование — `Ctrl+D`. Фавиконка
   — синяя буква **A** (встроенный SVG в `data:`-URI, без отдельного файла).
2. **Библиотека блоков** — разделы Aura X (Миксы / Звуковые схемы, см. ниже) и
   legacy-пресеты, скрытые из палитры (Гудок, Тифон, Компрессор и т.д.), которые
   продолжают работать в старых проектах. Цветовая градация по группам.
   Примитивы звуковой схемы (`Старт`, `Простой`, `Цикл`, `Пауза`, `Конец`)
   собираются цепочкой связей `after` в произвольные сценарии.

   **Примитивы звуковой схемы** (группа «Звуковая схема») собираются в цепочку
   связями «цепочка звуков» (`after`) и позволяют строить произвольные сценарии
   из небольших кирпичиков вместо готовых пресетов. У каждого блока свой набор
   полей:
   - `Старт` — **стартовая часть звука**. WAV + громкость + **запуск** («Авто/
     F-клавиша/двигатель/скорость/направление») + выход. Играет один раз по
     запуску, затем передаёт управление дальше. Порт только выходной (это начало
     схемы).
   - `Простой звук` — **часть звука**: WAV + громкость + выход («Напрямую/После
     события» + задержка). Запуска не имеет — приходит по связи и играет раз.
   - `Цикл` — **цикличный звук**: WAV + громкость + **завершение цикла** + выход.
     Варианты завершения: «Пока активно» (по событию запуска схемы), «По времени»
     (длительность в мс), «По количеству раз» (N повторов, поле состояния
     `loops`; после N-го проигрывания идёт `sample_done`) или «По событию»
     (двигатель стоп / смена направления / F-клавиша схемы). Затем идёт дальше
     по связи.
   - `Пауза` (Mute) — тишина без WAV: только **длительность паузы, мс**; затем
     дальше по связи.
   - `Конец` — **последняя часть звука**: WAV + громкость; порта выхода нет
     (терминатор ветки).

   Цепочка строится как `Старт → (Простой/Цикл/Пауза)* → Конец` связями
   «цепочка звуков»; каждая связь передаёт управление дальше (по завершении
   звука, по завершению цикла или по истечении паузы).
3. **Компилятор звуковых блоков → схема устройства** (`sound-graph`, schema v1):
   состояния/переходы, тихие входы, `effects`, приоритеты, `immediate`/
   `after_sample` проставляются автоматически.
4. **Компилятор блоков выходов/логики → привязки** `func_binding_t`:
   - `Фары` → `FUNC_TARGET_OUTPUT` id 0 (F0F, dir=вперёд) и/или id 1 (F0R, dir=назад)
     в зависимости от направления (`Авто/вперёд/назад/без направления`);
   - `AUX-выход` → `FUNC_TARGET_OUTPUT` id 2..8 (AUX1..7);
   - `Логика` → `FUNC_TARGET_LOGIC` (mute стоп/ход/свет, удержание хода,
     выбег, дин. тормоз, набор/сброс позиции);
   - уровень и эффект AUX пишутся в `/api/aux/cfg`
     (постоянный, лампа накаливания, Марс, ходовые, маяк, строб, топка).
5. **Холст**:
   - перетаскивание блоков мышью/пальцем, pan (тянуть фон средней/правой
     кнопкой), zoom (колесо);
   - **выделение нескольких блоков**: рамкой (протяжка левой кнопкой по фону)
     или Shift/Ctrl+клик по блокам; выделенные блоки перетаскиваются группой, а
     клавиша **Del/Backspace** (или крестик в заголовке блока) удаляет всю выборку
     (двигатель и громкость защищены от удаления);
   - **привязка к сетке** (тумблер «Сетка» в меню «Настройки»). Сетка рисуется
     на всём видимом
     холсте (не кончается при панорамировании) и совпадает с мировыми
     координатами; блок 240×80 и координаты кратны
     шагу 20, входы/выходы — по центру боковых сторон и попадают точно в узлы
     сетки; цвет блока и заголовка соответствует группе (двигатель, сигналы,
     механика, свет/выходы, освещение, дополнительно);
   - **соединение мышью с живым предпросмотром**: во время протяжки рисуется
     пунктирная линия; на конце — маленькая стрелка-галочка (SVG marker),
     выровненная точно по центру круга входа и не заходящая под него;
   - **метки входа и выхода** на каждом блоке и цветные порты
     (синий — вход, зелёный — выход);
   - **связь выделяется кликом**: у каждой линии есть невидимая утолщённая
     область попадания (~16 px, не зависит от зума), поэтому по ней легко
     попасть; выделенная связь удаляется клавишей **Del/Backspace** или кнопкой
     «Удалить связь» в инспекторе.
   - **подписи на поле**: кнопка **T** на верхней панели (рядом с **↶**/**↷**)
     включает режим добавления произвольного текста — клик по пустому месту
     холста создаёт подпись (для подписывания участков схемы и пояснений).
     Подпись перетаскивается мышью, двойной клик — правка прямо на холсте
     (`Enter` — применить, `Esc` — отменить), в инспекторе настраиваются текст,
     размер и цвет; `Del`/`Backspace` или «Удалить» в инспекторе убирают подпись.
     Подписи хранятся в проекте (черновик, экспорт/импорт JSON) и участвуют в
     отмене/повторе; режим снимается повторным нажатием **T** или `Esc`.
6. **Инспектор**: зависит от типа блока — F-клавиша, громкость/яркость, режим
   запуска, WAV по ролям, ступени скорости, направление фар, AUX-канал,
   эффект освещения, логическая операция. Список WAV — из `/api/audio/tracks`.
7. **Связи**:
   - `Двигатель → звуковой блок` включает режим «При двигателе»
     (`engine_on`/`engine_off` вместо F-клавиши);
   - `звуковой блок → блок выхода/логики` передаёт блоку F-клавишу источника
     (маршрутизация привязки на тот же F);
   - прочие связи — организационные (см. «Что надо будет сделать»).
8. **Проверка**: клиентская (лимиты, тихие входы, приоритеты, ссылки, каналы)
   + серверная `/api/sound/graph/validate`; отсутствующие WAV — предупреждение.
   Отдельного меню «Проверка» нет — проверка выполняется внутри блока
   (**«▶ Тест блока»** в инспекторе), а полная валидация запускается при
   «Сохранить».
9. **Запись/применение**:
   - «Сохранить» — сохраняет граф (`/api/sound/graph/save`), применяет его на
     устройстве (`/api/sound/graph/apply`) и записывает привязки выходов
     (`/api/func-map?bind=1`) и AUX-эффекты (`/api/aux/cfg`).
   Привязки, созданные редактором, отслеживаются и удаляются при изменении
   схемы; чужие привязки не трогаются.
10. **Локальный черновик** в `localStorage`; экспорт/импорт JSON (`*.blocks.json`).
11. **Раздача без правок C-кода**: `public/blocks.html` копируется сборочным
    скриптом в `dist/`, существующий `sound_editor_get` отдаёт файл. `public/`
    включён в проверку свежести сборки (`scripts/package-assets.mjs` и
    `tools/gen_sound_editor.py`).
12. **Пункт меню**: отдельная панель в `firmware/web_ui.html`.
13. **Выбор и прослушивание звуков**: в инспекторе файл выбирается списком —
    группа «На устройстве» (слоты `slotNN.wav`) и группа «Тест (SOUND)»
    (`*.wav` из папки `SOUND/`). Кнопка ▶ у поля проигрывает выбранный файл:
    в превью — по `/sound-files/<имя>` (папку раздаёт `mock_server.py`),
    на устройстве — слот через `/api/audio/play`. Папка `SOUND/` — локальный
    тестовый материал, в git не коммитится.
14. **Тесты**: кнопка **«▶ Тест блока»** в инспекторе проверяет выбранный блок
    (наличие файлов, источника F, лимиты, серверную валидацию) и проигрывает
    его звук; отчёт выводится в панели диагностики. Кнопки общей проверки схемы
    на панели больше нет — валидация всей схемы выполняется неявно при
    «Сохранить».
15. **Тема**: редактор использует общий для всех страниц ключ `aura_theme` и
    атрибут `html[data-theme]`; кнопка ☀/☾ переключает светлую/тёмную тему,
    выбор общий с основным интерфейсом.
16. **Скорость, направление, случайность, ducking**:
    - блок `Скоростной звук` — диапазоны скорости в процентах (по умолчанию
      шаг 25 %) со своим WAV на диапазон и защитным интервалом (по умолчанию
      5 %); при добавлении/удалении ступени проценты пересчитываются поровну;
    - у звуковых блоков запуск можно задать «По скорости» (от/до %, защита) или
      «По направлению» (вперёд/назад);
    - `Тормоз` играет по замедлению (условие `decel`);
    - блок `Случайный звук` — при нажатии F играет один случайный файл из списка
      (условие `random`, равновероятный выбор);
    - **ducking**: пока звучит любой эффект, громкость двигателя автоматически
      снижается до 40 % и восстанавливается, когда эффект закончился;
    - проценты переводятся в шкалу движка 0..255, защитный интервал уходит в
      общий `hysteresis` графа.

Движок (прошивка) расширен под это: условия `dir_fwd`/`dir_rev`/`random`,
передача направления в `sg_runner_tick()`, ГПСЧ в раннере и живое изменение
громкости голоса (`audio_voice_set_volume_live`) для ducking.
17. **Работа с блоками и подписями**: отмена/повтор (`Ctrl+Z`/`Ctrl+Y`, кнопки
    ↶/↷), копирование и вставка (`Ctrl+C`/`Ctrl+V`, а также `Ctrl+Insert`/
    `Shift+Insert`) — в том числе сразу нескольких выделенных блоков и подписей;
    вставленный блок встаёт со смещением и новой F-клавишей, подпись — со
    смещением и новым `id`. Дублирование выделенного — `Ctrl+D`. Горячие клавиши
    определяются по `event.code`, поэтому работают на любой раскладке (в т.ч.
    русской).
18. **Предупреждения о конфликтах**: одинаковые F-клавиши у нескольких блоков
    или двигателя показываются предупреждением (не блокируют сохранение).
19. **Семантические связи**: связь «звук → звук» = цепочка. У блока-источника
    настраивается **выход**: «Напрямую» или «После события», и **задержка в мс**
    (0 — сразу). «Двигатель → блок» — гейт, «блок → выход/логика» — привязка.
    Вход блока — это его условие запуска (F-клавиша, двигатель, скорость,
    направление, связь).
20. **Готовность блока**: у правильно настроенного блока в заголовке зелёная
    галочка ✓ (учитывает файлы, канал/операцию и ошибки блока).
21. **Скорость в процентах**: ступени двигателя задаются диапазонами % с
    защитным интервалом (по умолчанию 5 %); у звуковых блоков — запуск
    «По скорости» (%); у блока «Скоростной звук» — диапазоны %. При добавлении
    ступени проценты пересчитываются поровну.
22. **Круговое чтение выходов**: при открытии подтягиваются привязки и AUX с
    устройства; кнопка «Импорт выходов» создаёт блоки фар/AUX/логики из них.
23. **Мобильная раскладка**: панели сворачиваются (☰/⚙), жесты панорамы/зума.
24. **Схема и таблица связей**: открываются пиктограммой на верхней панели
    в отдельном окне. Внутри — мини-схема связей (блоки
    цветом по группам, стрелки) и текстовая **таблица связей**
    («источник → цель → условие»). Кнопка **«Скачать картинку»** сохраняет
    подробную PNG-схему: карточки блоков с названиями и содержимым (файлы,
    ступени %, канал/эффект, выход) и подписи условий на связях. Кнопка
    **«Скачать текст»** — `.txt` с логикой (блоки с параметрами и связи с
    условиями). В панели свойств блока эта информация не показывается.

## Миксы и звуковые схемы (модель Aura X)

Палитра разделена на два раздела, как в макете Aura X:

- **Основные**: `Двигатель`, `Громкость` (настройки устройства).
- **Миксы**: `Вход (Fx)`, `Выход (AUX/Свет)`, `Звук`, `Логика`,
  `Установить переменную`, `Задержка`.
- **Звуковые схемы**: `Старт`, `Простой`, `Цикл`, `Конец`, `Пауза`, а также
  `Логика`, `Установить переменную`, `Задержка`.

Именованные пресеты (Гудок, Тифон, Звонок, Компрессор, Тормоз и т.д.) остаются
в файлах старых проектов, но не показываются в палитре: по Aura X любой сценарий
(Whistle, Horn, Compressor, Brake) собирается из простых блоков и переменных без
жёстко зашитой логики.

### Глобальные переменные

Модель переменных общая для обоих разделов:

- встроенные статусы (только чтение): `speed` (0..255), `forward` (0/1),
  `moving` (0/1), `engine` (0/1);
- пользовательские переменные (имя + начальное значение).

Отдельная панель «Переменные» в правой колонке удалена (как и сводка проверки и
кнопки «Готово»/«Удалить» в инспекторе). Встроенные статусы продолжают работать;
пользовательские переменные по-прежнему хранятся в проекте и схеме (`variables`)
и остаются в JSON при экспорте/импорте.

### Блок «Логика»

Читает глобальные переменные и выдаёт **True/False**. Условия объединяются через
**AND** или **OR**, операторы сравнения `=`, `!=`, `<`, `<=`, `>`, `>=`; у
каждого условия есть флаг **NOT** (логическое отрицание). Два выхода
(True/False) — отдельные порты на блоке; связь от нужного порта задаёт ветвь.

### Блок «Вход (Fx)»

**Один выход**; выбирается F-клавиша и **режим Fx**:
- **Вкл/выкл** — срабатывание по нажатию (`fn_press`);
- **Удержание** — активно, пока клавиша удерживается (`fn_on`);
- **Строб** — то же удержание (`fn_on`); само мигание выполняет целевой блок
  (световой эффект «Строб» у `Выхода` или цикл звука).

Один выход может запускать несколько блоков (ветвление, см. ниже).

### Блок «Пауза (Mute)»

Чекбокс **«Прекратить воспроизведение сейчас»** плюс установка громкости в 0.
В графовой модели блок представлен тихим состоянием.

### Ветвление (fan-out)

`Вход (Fx)` — **источник триггера**: каждая связь с его выхода не «тянет один
токен», а **назначает условие запуска** целевому блоку. Поэтому один выход Fx
может запускать **несколько блоков одновременно** (как в примерах 2–3 макета:
`Input (F1) On → Output (Light) + Sound (Horn) + Logic`). Каждый целевой блок
становится отдельным каналом (`effect`) и тикает параллельно; блочные звуки
после проигрывания возвращаются в свой вход и перезапускаются на следующем
событии. Логика/переменная/задержка без исходящих связей тоже возвращаются во
вход (перезапуск по событию).

Ветвление из выходов **других** блоков (Sound/Logic/Var/Delay) пока не
поддерживается — там сохраняется одна ветка, и проверка выдаёт предупреждение.
Предел — `SG_MAX_EFFECTS = 24` каналов.

### Уникальность и задержки

- «Вход (Fx)» — один блок на F; «Выход (AUX/Свет)» — один блок на канал;
  дубли показываются предупреждением в проверке.
- Пер-блочная задержка у блоков звуковых схем убрана: пауза задаётся отдельным
  блоком **Задержка** (как в макете).

### Блок «Установить переменную»

Присваивает пользовательской переменной значение. Без входной связи выполняется
при запуске (как описано в макете: «если не подключен Вход, то выполняется при
запуске»).

### Блок «Выход (AUX/Свет)»

Объединяет прежние `Фары` и `AUX-выход`: в настройках выбирается канал
(`Фары`, `AUX1..AUX7`), световой эффект и яркость. Компилируется в привязки
`func_binding_t` (`FUNC_TARGET_OUTPUT`) и `/api/aux/cfg` по F-клавише источника.

### Прошивка

Формат графа расширен обратно совместимо (schema v1):

- `variables` — до `SG_MAX_VARIABLES = 16` переменных (встроенные + пользовательские);
- поля состояния `setVar`/`setValue` — присваивание при входе в состояние;
- условие `var_cmp` — `var`, `op` (0..5), значение либо `var2` (сравнение двух
  переменных).

Рантайм (`sound_graph_runner.c`) хранит значения пользовательских переменных,
вычисляет встроенные статусы на каждом такте и применяет `setVar` при входе.
Валидатор (`sound_graph.c`) проверяет имена/лимиты переменных, корректность
`var_cmp` и то, что `setVar` указывает на пользовательскую переменную. Схемы без
переменных (старые) парсятся как раньше. Покрыто `test_sound_graph`.

Компилятор редактора строит для блока «Логика» цепочку тихих состояний с
условиями `var_cmp` (AND — последовательно, OR — с ветвью «иначе»), а
`Установить переменную`/`Задержка` — тихие состояния с `setVar` и `timeout`.

## Аудит блоков (дубли и пробелы)

Убрано как дубли:
- `Световой эффект` — дублировал `AUX-выход` (световой эффект настраивается
  внутри AUX).
- `Короткий сигнал` — совпадал с `Тифон`; короткий/длинный уже даёт `Гудок`
  (режим «короткий/длинный»).

Оставлены как именованные пресеты с одинаковой логикой `oneshot`:
`Тифон`, `Сцепка`, `Песочница`, `Токоприёмник`, `Двери` — отличаются названием
и звуком, это удобные заготовки.

Реализовано:
- запуск по скорости и состоянию (`speed`) и по направлению (`dir_fwd`/`dir_rev`),
  тормоз по замедлению (`decel`), скоростные диапазоны в процентах (шаг 25 %,
  защита по умолчанию 5 %);
- случайный выбор звука (условие `random`);
- ducking двигателя под эффектами.

Прошивные изменения: `sound_graph.h` (условия и поля раннера),
`sound_graph_runner.c` (направление, ГПСЧ, выбор из random-группы),
`sound_graph.c` (парсер и валидация), `audio.c`/`audio.h`
(`audio_voice_set_volume_live`), `sound.c` (передача направления и ducking).
Покрыто host-тестами `test_sound_graph` (направление, random, разбор JSON) и
`test_audio` (аудио-компоненты с новым API).

## Как пользоваться

1. Открыть `/sound-editor/blocks.html` (или Настройки → «Конструктор звуков»).
2. Добавить блоки из палитры слева; сетку при необходимости выключить.
3. Выбрать блок и заполнить справа: F-клавишу, WAV-файлы (список: устройство
   или тестовая папка `SOUND`), канал/эффект. Кнопка ▶ прослушивает звук.
4. Протянуть связи: от «выхода» одного блока к «входу» другого (со стрелкой).
5. «▶ Тест блока» в инспекторе — проверка выбранного блока и его звука.
6. «Сохранить» (сохраняет и сразу применяет схему).

## Как менять исходник

```powershell
cd firmware\sound_editor
npm run build          # public\blocks.html -> dist\blocks.html
# или: node scripts\package-assets.mjs
# или: ..\build_sound_editor.ps1
```

Сборка не требует `npm install` и внешних пакетов — только Node.js (встроенные
модули). После правки обязательно пересобрать и закоммитить `dist/blocks.html`
и `dist/build-inputs.json` — иначе сборка прошивки отклонит устаревшие ассеты
(`build-inputs.json`).

## Что надо будет сделать

- **Автоматические тесты** (в дополнение к встроенным кнопкам теста): unit для
  компилятора. Требует вынести чистую логику компиляции в отдельный модуль.
- **Обратная сборка из схемы устройства** (полная): сейчас есть импорт привязок
  выходов/логики как блоков и чтение привязок; звуковые блоки восстанавливаются
  из черновика/импорта.
- **`min_ms`/`fade_ms`/`short_ms`** — относятся к привязкам `func_binding_t`,
  которые в графовом режиме для звуков не используются.

## Ограничения движка (учитывать при добавлении блоков)

`SG_MAX_STATES 57`, `SG_MAX_TRANSITIONS 128`, `SG_MAX_EFFECTS 24`
(`firmware/components/sound/include/sound_graph.h`); привязок до
`FUNC_BIND_MAX 64` (`func_types.h`). Каждый блок расходует состояния/переходы
и, для выходов, привязки; редактор показывает остаток бюджета.
