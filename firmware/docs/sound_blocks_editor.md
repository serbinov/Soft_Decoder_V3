# Конструктор звуковых блоков (sound blocks editor)

Единственный редактор звуковой схемы тепловоза — собирается из **готовых
блоков**. Страница написана на ванильном HTML/CSS/JS без фреймворков и внешних
зависимостей; открывается по адресу `/sound-editor/blocks.html`.

- Исходник (правится): `firmware/sound_editor/public/blocks.html`
- Собранная копия (в git): `firmware/sound_editor/dist/blocks.html`
- Пункты в интерфейсе: Настройки → «Миксы» и «Звуковые схемы» (один редактор,
  `?mode=mix` / `?mode=scheme`)

## Что сделано

1. **Приложение редактора** — `firmware/sound_editor/public/blocks.html`:
   палитра, холст, инспектор, диагностика, тулбар. Без внешних зависимостей.
   Верхняя панель сгруппирована по функционалу в выпадающие меню (Файл,
   Настройки): в «Файле» — новая схема, **загрузка проекта с устройства**,
   импорт/экспорт JSON, **импорт выходов/AUX**, проверка схемы и блоков,
   **симулятор**, поля имени/ID проекта и экспорт блок-схемы картинкой (JPG) или
   текстом (TXT, логика), в «Настройках» — сетка, тема и язык. Кнопки не расползаются на узких экранах; ключевые действия
   («Сохранить», «Выйти») остаются на виду. После меню «Файл» идут три кнопки:
   **T** («Добавить текст», см. «Холст» ниже), **↶** (Отменить) и **↷**
   (Повторить). Копирование/вставка выделенного — блоков и подписей —
   горячими клавишами (`Ctrl+C` / `Ctrl+V`), дублирование — `Ctrl+D`. Фавиконка
   — синяя буква **A** (встроенный SVG в `data:`-URI, без отдельного файла).
2. **Библиотека блоков** — разделы Aura X (Миксы / Звуковые схемы), цветовая
   градация по группам. Legacy-пресеты («Готовые звуки»: Гудок, Тифон,
   Компрессор, Случайный звук и т.д.) в палитре больше не показываются, но
   остаются в старых проектах и JSON. Примитивы звуковой схемы (`Старт`,
   `Простой`, `Цикл`, `Пауза`, `Конец`) собираются цепочкой связей `after`
   в произвольные сценарии.

   **Примитивы звуковой схемы** (группа «Звуковая схема») собираются в цепочку
   связями «цепочка звуков» (`after`) и позволяют строить произвольные сценарии
   из небольших кирпичиков вместо готовых пресетов. У каждого блока свой набор
   полей:
- `Старт` — **стартовая часть звука**. WAV + громкость + выход. Собственного
поля Trigger/F-клавиши нет, но есть входной порт (связь может отсутствовать),
поэтому `Старт` не обязан быть первым блоком схемы. Играет один раз по запуску,
затем передаёт управление дальше.
   - `Простой звук` — **часть звука**: WAV + громкость + задержка выхода.
     Запуска не имеет — приходит по связи и играет раз; следующий блок
     запускается после завершения.
   - `Цикл` — **цикличный звук**: WAV + громкость + **завершение цикла** + выход.
     Варианты завершения: «Пока активно» (по событию запуска схемы), «По времени»
     (длительность в мс), «По количеству раз» (N повторов, поле состояния
     `loops`; после N-го проигрывания идёт `sample_done`) или «По событию»
     (двигатель стоп / смена направления / F-клавиша входного блока). Для
     `toggle`-входа повторное нажатие завершает цикл, для `hold` — отпускание
     клавиши. Затем идёт дальше по связи.
   - `Пауза` (Mute) — тишина без WAV: только **длительность паузы, мс**; затем
     дальше по связи.
   - `Конец` — **последняя часть звука**: WAV + громкость; порта выхода нет
     (терминатор ветки).

   Цепочка строится как `(Пауза/Логика)* → Старт → (Простой/Цикл/Пауза)* → Конец`
   связями
   `after`; `Старт` не обязателен — схема может состоять из одного `Цикла`
   (так сделаны четыре схемы двигателя по ступеням скорости).
   «цепочка звуков»; каждая связь передаёт управление дальше (по завершении
   звука, по завершению цикла или по истечении паузы).
3. **Компилятор звуковых блоков → схема устройства** (`sound-graph`, schema v1):
   состояния/переходы, тихие входы, `effects`, приоритеты, `immediate`/
   `after_sample` проставляются автоматически.
4. **Компилятор блоков выходов/логики → привязки** `func_binding_t`:
   - `Фары` → `FUNC_TARGET_OUTPUT` id 0 (F0F, dir=вперёд) и/или id 1 (F0R, dir=назад)
     в зависимости от направления (`Авто/вперёд/назад/без направления`);
   - `AUX-выход` → `FUNC_TARGET_OUTPUT` id 2..8 (AUX1..7);
   - `Логика` (графовая) → условия `var_cmp` внутри схемы; при прямой связи
     `Логика → Выход/Логический выход` те же условия компактно переносятся в
     `func_binding_t` (до двух сравнений с числом, `AND`/`OR`, инверсия False);
   - `Логический выход` → `FUNC_TARGET_LOGIC` id 1..8 (mute стоп/ход/свет,
     удержание хода, выбег, дин. тормоз, набор/сброс позиции). Рантайм:
     mute-сигналы глушат звук графа в соответствующем состоянии, удержание
     хода замораживает скорость/позицию, выбег и дин. тормоз переводят граф
     на idle, а notch up/down срабатывают по фронту и сдвигают скорость графа
     в диапазоне -24..+24; сами привязки исполняет `web_apply_function()`.
   - уровень и эффект AUX/фар пишутся в `/api/aux/cfg` по индексам устройства
     `0=F0F, 1=F0R, 2..8=AUX1..7` (постоянный, лампа накаливания, Марс, ходовые,
     маяк, строб, топка). В редакторе канал 0 = «Фары», 1..7 = AUX1..7.
   **Проекты и устройство:** редакторская копия проекта вкладывается в
   игнорируемый прошивкой объект `editor.project` (при размере до 120 КБ), поэтому
   «Загрузить с устройства» восстанавливает не только граф, но и Mixes/схемы.
   «Импорт выходов» читает `/api/func-map` и `/api/aux/cfg`, создаёт блоки
   `Выход`/`Логический выход` с входными Fx-связями и восстанавливает условия
   через блоки `Логика`. **Симулятор** (кнопка в шапке, ▶ на блоке `Звук` или
   кнопка в инспекторе) запускает скомпилированный граф — в Mixes весь микс,
   в режиме схем активную схему; заранее подтягивает длительности WAV, проигрывает их
   через браузер ПК (AudioContext разблокируется синхронно по клику) и показывает
   F-кнопки, скорость, направление, двигатель,
   состояния каналов, активные выходы/AUX, активные логические действия и
   журнал переходов. Live включён всегда (отдельной кнопки нет) и опрашивает
   `/api/sound/graph/state` и подсвечивает на схеме блоки, в которых реально
   находится запущенный граф, а также связи, касающиеся этих блоков; в Mixes
   подсвечивается блок `Звук` (cue), в режиме схем — активный внутренний блок.
   Если открыт **Симулятор**, Live автоматически переключается на его локальное
   состояние и показывает активные блоки без запросов к декодеру; после закрытия
   симулятора возвращается к данным устройства. Неактивные каналы, стоящие в
   тихом состоянии `_off`, не подсвечиваются, поэтому при простое не горят все
   cue сразу. Активные выходы (`Фары`, `AUX1..AUX7`), логические выходы и
   `Вход (Fx)` тоже подсвечиваются; вход горит, пока соответствующая F-клавиша
   включена (toggle/hold/strobe), на блоке фар показывается активное направление
   `F0F`/`F0R`.
   При открытии конструктор сначала загружает с декодера проект, который сейчас
   активен в работе; локальный черновик используется, только если он относится
   к этому же проекту или связи нет. Для device-режима подсветка работает
   только для сохранённого/запущенного на устройстве графа.
5. **Холст**:
   - перетаскивание блоков мышью/пальцем, pan (тянуть фон средней/правой
     кнопкой), zoom (колесо);
   - **выделение нескольких блоков**: рамкой (протяжка левой кнопкой по фону)
     или Shift/Ctrl+клик по блокам; выделенные блоки перетаскиваются группой, а
     клавиша **Del/Backspace** (или крестик в заголовке блока) удаляет всю выборку
     (двигатель и громкость защищены от удаления);
   - **привязка к сетке** (тумблер «Сетка» в меню «Настройки»). Сетка рисуется
     на всём видимом
     холсте (не кончается при панорамировании) и совпадает с мировыми
     координатами; блок 240×80 и координаты кратны
     шагу 20, входы/выходы — по центру боковых сторон и попадают точно в узлы
     сетки; цвет блока и заголовка соответствует функции блока (вход, выход,
     `Звук`, логика, переменная, задержка, `Старт/Простой/Цикл/Конец/Пауза`,
     двигатель, громкость; для legacy-пресетов — цвет группы).
   - **соединение мышью с живым предпросмотром**: во время протяжки рисуется
     пунктирная линия; на конце — маленькая стрелка-галочка (SVG marker),
     выровненная точно по центру круга входа и не заходящая под него;
   - **метки входа и выхода** на каждом блоке и цветные порты
     (синий — вход, зелёный — выход);
   - **связь выделяется кликом**: у каждой линии есть невидимая утолщённая
     область попадания (~16 px, не зависит от зума), поэтому по ней легко
     попасть; выделенная связь удаляется клавишей **Del/Backspace** или кнопкой
     «Удалить связь» в инспекторе.
   - **подписи на поле**: кнопка **T** на верхней панели (рядом с **↶**/**↷**)
     включает режим добавления произвольного текста — клик по пустому месту
     холста создаёт подпись (для подписывания участков схемы и пояснений).
     Подпись перетаскивается мышью, двойной клик — правка прямо на холсте
     (`Enter` — применить, `Esc` — отменить), в инспекторе настраиваются текст,
     размер и цвет; `Del`/`Backspace` или «Удалить» в инспекторе убирают подпись.
     Подписи хранятся в проекте (черновик, экспорт/импорт JSON) и участвуют в
     отмене/повторе; режим снимается повторным нажатием **T** или `Esc`.
6. **Инспектор**: зависит от типа блока — громкость/яркость, режим
   запуска, WAV по ролям, ступени скорости, направление фар, AUX-канал,
   эффект освещения, логическая операция. **F-клавиша есть только у блока
   `Вход (Fx)`**; у остальных блоков поля F нет — триггер приходит по связи.
   Список WAV — из `/api/sound-files` (установленные на устройстве файлы).
7. **Связи**:
   - `Вход (Fx) → блок` назначает блоку условие запуска (`fn_press`/`fn_on`);
   - `Двигатель → звуковой блок` включает режим «При двигателе»
     (`engine_on`/`engine_off`);
   - `звуковой блок/Логика → блок выхода` маршрутизирует привязку на F-клавишу
     входного блока, от которого идёт цепочка (у выхода своей F нет);
   - прочие связи — организационные (см. «Особенности текущей реализации»).
8. **Проверка**: клиентская (лимиты, тихие входы, приоритеты, ссылки, каналы)
   + серверная `/api/sound/graph/validate`; отсутствующие WAV — предупреждение.
   Отдельного меню «Проверка» нет — проверка выполняется внутри блока
   (**«▶ Тест блока»** в инспекторе), а полная валидация запускается при
   «Сохранить».
9. **Запись/применение**:
   - «Сохранить» — сохраняет граф (`/api/sound/graph/save`), применяет его на
     устройстве (`/api/sound/graph/apply`) и записывает привязки выходов
     (`/api/func-map?bind=1`) и AUX-эффекты (`/api/aux/cfg`).
   Привязки, созданные редактором, отслеживаются и удаляются при изменении
   схемы; чужие привязки не трогаются.
10. **Локальный черновик** в `localStorage`; экспорт/импорт JSON (`*.blocks.json`).
11. **Раздача без правок C-кода**: `public/blocks.html` копируется сборочным
    скриптом в `dist/`, существующий `sound_editor_get` отдаёт файл. `public/`
    включён в проверку свежести сборки (`scripts/package-assets.mjs` и
    `tools/gen_sound_editor.py`).
12. **Пункт меню**: отдельная панель в `firmware/web_ui.html`.
13. **Выбор и прослушивание звуков**: в инспекторе файл выбирается списком —
    группа «На устройстве» (слоты `slotNN.wav`) и группа «Тест (SOUND)»
    (`*.wav` из папки `SOUND/`). Кнопка ▶ у поля проигрывает выбранный файл:
    по умолчанию в браузере ПК через `/sound-files/<имя>` (на устройстве этот
    маршрут отдаёт PCM16, ADPCM декодируется на лету). Кнопка
    «Воспроизведение: ПК/декодер» в шапке редактора переключает прослушивание;
    её выбор хранится отдельно от страницы звуков. Папка `SOUND/` — локальный
    тестовый материал, в git не коммитится.
14. **Тесты**: кнопка **«▶ Тест блока»** в инспекторе проверяет выбранный блок
    (наличие файлов, источника F, лимиты, серверную валидацию) и проигрывает
    его звук; отчёт выводится в панели диагностики. Кнопки общей проверки схемы
    на панели больше нет — валидация всей схемы выполняется неявно при
    «Сохранить».
15. **Тема**: редактор использует общий для всех страниц ключ `aura_theme` и
    атрибут `html[data-theme]`; кнопка ☀/☾ переключает светлую/тёмную тему,
    выбор общий с основным интерфейсом.
16. **Скорость, направление, случайность, ducking**:
    - блок `Скоростной звук` — диапазоны скорости в процентах (по умолчанию
      шаг 25 %) со своим WAV на диапазон и защитным интервалом (по умолчанию
      5 %); при добавлении/удалении ступени проценты пересчитываются поровну;
    - у звуковых блоков запуск можно задать «По скорости» (от/до %, защита) или
      «По направлению» (вперёд/назад);
    - `Тормоз` играет по замедлению (условие `decel`);
    - блок `Случайный звук` — по входному триггеру играет один случайный файл из списка
      (условие `random`, равновероятный выбор);
    - **ducking**: пока звучит любой эффект, громкость двигателя автоматически
      снижается до 40 % и восстанавливается, когда эффект закончился;
    - проценты переводятся в шкалу движка 0..255, защитный интервал уходит в
      общий `hysteresis` графа.

Движок (прошивка) расширен под это: условия `dir_fwd`/`dir_rev`/`random`,
передача направления в `sg_runner_tick()`, ГПСЧ в раннере и живое изменение
громкости голоса (`audio_voice_set_volume_live`) для ducking. Раздельные
громкости `engine_volume`/`effects_volume` теперь реально масштабируют состояния
графа (двигатель/эффекты), а `master_volume` применяется общим микшером.
17. **Работа с блоками и подписями**: отмена/повтор (`Ctrl+Z`/`Ctrl+Y`, кнопки
    ↶/↷), копирование и вставка (`Ctrl+C`/`Ctrl+V`, а также `Ctrl+Insert`/
    `Shift+Insert`) — в том числе сразу нескольких выделенных блоков и подписей;
    вставленный блок встаёт со смещением (для `Входа (Fx)` — с новой F-клавишей), подпись — со
    смещением и новым `id`. Дублирование выделенного — `Ctrl+D`. Горячие клавиши
    определяются по `event.code`, поэтому работают на любой раскладке (в т.ч.
    русской).
18. **Предупреждения о конфликтах**: одинаковые F-клавиши у нескольких блоков
    `Вход (Fx)` показываются предупреждением (не блокируют сохранение).
19. **Семантические связи**: связь «звук → звук» = цепочка. У `Старта` и
    legacy-пресетов (`one-shot`, `short-long`, `decel`, `loop-held`)
    настраивается **выход**: «Напрямую» или «После события», и **задержка в мс**
    (0 — сразу). У `Простого`/`Цикла` выход всегда «После события». «Двигатель →
    блок» — гейт, «блок → выход/логика» — привязка. Вход блока — это его условие
    запуска: связь от `Входа (Fx)`, выход `Логики`, двигатель, скорость или
    направление.
20. **Готовность блока**: у правильно настроенного блока в заголовке зелёная
    галочка ✓ (учитывает файлы, канал/операцию и ошибки блока).
    **Глобальные блоки** (`Логика`, `Переменная`, `Задержка` без входа)
    вычисляются один раз при запуске; граф получает `observers=true`, а
    исходящие связи используют условие `state_enter` и не повторяются каждый
    тик. Для повторной оценки подключите `Вход (Fx)`.
21. **Скорость в процентах**: ступени двигателя задаются диапазонами % с
    защитным интервалом (по умолчанию 5 %); у звуковых блоков — запуск
    «По скорости» (%); у блока «Скоростной звук» — диапазоны %. При добавлении
    ступени проценты пересчитываются поровну.
22. **Чтение/импорт выходов**: при открытии подтягиваются привязки и AUX с
    устройства; кнопка «Импорт выходов» создаёт/обновляет блоки
    `Выход`/`Логический выход` и входные Fx-связи.
23. **Мобильная раскладка**: панели сворачиваются (☰/⚙), жесты панорамы/зума.
    На телефоне выбор блока или связи автоматически открывает инспектор, поэтому
    настройки блока и кнопка «Удалить связь» доступны без клавиши Delete.
24. **Схема и таблица связей**: открываются пиктограммой на верхней панели
    в отдельном окне. Внутри — мини-схема связей (блоки
    цветом по функциям блоков, стрелки) и текстовая **таблица связей**
    («источник → цель → условие»). Кнопка **«Скачать картинку»** сохраняет
    подробную PNG-схему: карточки блоков с названиями и содержимым (файлы,
    ступени %, канал/эффект, выход) и подписи условий на связях. Кнопка
    **«Скачать текст»** — `.txt` с логикой (блоки с параметрами и связи с
    условиями). В панели свойств блока эта информация не показывается.

## Миксы и звуковые схемы (модель Aura X)

В главном меню веб-интерфейса два раздела — **Миксы** и **Звуковые схемы**;
оба открывают один и тот же офлайн-редактор с параметром `?mode=mix` или
`?mode=scheme`. Внутри редактора остаётся переключатель режима в шапке.

- **Mixes** — одна схема связей входов/выходов/логики, где блок `Звук` ссылается
  на именованную звуковую схему по имени.
- **Sound schemes** — отдельные именованные звуковые схемы. В левой панели над
  палитрой первым идёт пункт «+ Новая схема», ниже — плитки существующих схем.
  Выбранная плитка подсвечивается; перо включает редактирование названия прямо
  в плитке, корзина в конце плитки удаляет именно эту схему. Блоки одной схемы
  не смешиваются с общей схемой связей.

Хранилище проекта — формат **v2**: `mix` (общая схема) + `schemes[]` (именованные
звуковые схемы). Старые проекты v1 (единый граф) при загрузке переносятся в `mix`.
Поля `blocks`/`links`/`texts` в рантайме указывают на активную схему.

Запись на устройство строится из режима **Mixes**. Блок `Звук` ссылается на
именованную схему; при компиляции схема **разворачивается в общий граф** (inline:
подсхема клонируется с префиксом id в точку блока), поэтому формат прошивки не
меняется — устройство по-прежнему получает один плоский `sound-graph`. Режим
звуковых схем — только редактор схем, сохранение на устройство идёт из Mixes.

Палитра зависит от режима; блоки другого раздела скрыты, а не заблокированы:

- **Миксы**: группы **Основные** (`Двигатель`, `Громкость`) и **Миксы**
  (`Вход (Fx)`, `Выход (AUX/Свет)`, `Звук`, `Логика`, `Переменная`, `Задержка`).
- **Звуковые схемы**: группа **Звуковые схемы** (`Старт`, `Простой`, `Цикл`,
  `Конец`, `Пауза`) и группа **Общие** (`Логика`, `Переменная`, `Задержка`).
  Legacy-пресеты («Готовые звуки») в этом режиме не показываются.

Блок **`Звук`** в миксах выбирает не звуковой файл, а именованную звуковую схему
(файлы используются только внутри звуковых схем). Своей F-клавиши у блока нет:
к нему обязательно должна подходить связь от `Входа (Fx)` (или `Логики`,
управляемой входом) — её триггер и запускает схему.

Именованные legacy-пресеты (Гудок, Тифон, Звонок, Компрессор, Тормоз и т.д.)
остаются в старых проектах и JSON, но в палитре 0.12 не показываются: новые
схемы собираются из примитивов и блоков `Звук` в Mixes. Это убирает дублирование
двух путей построения звука и оставляет в палитре только блоки активного режима.

### Глобальные переменные

Модель переменных общая для обоих разделов:

- встроенные статусы (только чтение): `speed` (0..255), `forward` (0/1),
  `moving` (0/1), `engine` (0/1);
- пользовательские переменные (имя + начальное значение).

Панель «Переменные» в правой колонке показывает встроенные статусы
(только чтение) и позволяет создавать, переименовывать и удалять
пользовательские переменные, задавать начальное значение `init`. Ту же
переменную можно создать прямо в блоке «Переменная»; она сразу появляется в
списке «Логики». Пользовательские переменные хранятся в проекте и схеме
(`variables`) и остаются в JSON при экспорте/импорте.

### Блок «Логика»

Читает глобальные переменные и выдаёт **True/False**. Условия объединяются через
**AND** или **OR**, операторы сравнения `=`, `!=`, `<`, `<=`, `>`, `>=`; у
каждого условия есть флаг **NOT** (логическое отрицание). Два выхода
(True/False) — отдельные порты на блоке; связь от нужного порта задаёт ветвь.

### Блок «Вход (Fx)»

**Один выход**; выбирается F-клавиша и **режим Fx**:
- **Вкл/выкл** — срабатывание по нажатию (`fn_press`);
- **Удержание** — активно, пока клавиша удерживается (`fn_on`);
- **Строб** — то же удержание (`fn_on`); само мигание выполняет целевой блок
  (световой эффект «Строб» у `Выхода` или цикл звука).

Один выход может запускать несколько блоков (ветвление, см. ниже).

### Блок «Пауза (Mute)»

Только **длительность паузы, мс** (по умолчанию 500, шаг 50, максимум 12 750).
В графовой модели это тихое состояние с переходом `timeout` обратно во вход и
таким же условием для исходящей связи. Отдельного «стоп сейчас» больше нет:
остановка всех голосов не выражается графовым условием.

### Ветвление (fan-out)

`Вход (Fx)` — **источник триггера**: каждая связь с его выхода не «тянет один
токен», а **назначает условие запуска** целевому блоку. Поэтому один выход Fx
может запускать **несколько блоков одновременно** (как в примерах 2–3 макета:
`Input (F1) On → Output (Light) + Sound (Horn) + Logic`). Каждый целевой блок
становится отдельным каналом (`effect`) и тикает параллельно; блочные звуки
после проигрывания возвращаются в свой вход. Если блок был достигнут цепочкой,
после завершения последнего звука канал возвращается во вход корня цепочки,
поэтому повторное нажатие F снова проигрывает всю схему. Логика/переменная/
задержка без исходящих связей тоже возвращаются во вход (перезапуск по событию).

Ветвление из выходов **других** блоков (Sound/Logic/Var/Delay) пока не
поддерживается — там сохраняется одна ветка, и проверка выдаёт предупреждение.
Предел — `SG_MAX_EFFECTS = 32` каналов. Канал создаётся только для реальной
точки входа (Fx, cue с входящей связью, прямой вход из связи), а блоки, достигнутые
только цепочкой `Старт → ...`, каналов не расходуют. Голосов в аудио 20:
голос 19 занимает двигатель, голос 18 зарезервирован за SELFTEST/HIL, поэтому
одновременно доступно не более **18** эффектов. `SG_MAX_EFFECTS = 32` — это
каналы графа, а не голоса: при нехватке голоса канал ждёт свободный голос и
повторяет попытку на следующем тике.

### Уникальность и задержки

- «Вход (Fx)» — один блок на F; «Выход (AUX/Свет)» — один блок на канал;
  дубли показываются предупреждением в проверке.
- У `Старта`, `Простого` и `Цикла` снова есть **задержка выхода** (`outDelay`, мс):
  она ставится после события блока и перед следующей связью. У `Паузы` это поле
  означает длительность самой паузы.

### Блок «Переменная»

Присваивает пользовательской переменной значение при входе в состояние блока.
Без входящей связи блок выполняется один раз при запуске (`observers=true`) и
перекрывает начальное значение `init` из панели **Переменные**. Если несколько
глобальных «Переменных» пишут одну и ту же переменную, побеждает последняя по
порядку каналов.

### Блок «Выход (AUX/Свет)»

Объединяет прежние `Фары` и `AUX-выход`: в настройках выбирается канал
(`Фары`, `AUX1..AUX7`), световой эффект, яркость, **направление** (`Авто/Вперёд/Назад/Без направления`)
и **состояние** (`Любое/В движении/Стоит`). Компилируется в привязки
`func_binding_t` (`FUNC_TARGET_OUTPUT`) и `/api/aux/cfg` по F-клавише входного
блока, от которого идёт цепочка (у выхода своей F нет).
Для канала `Фары` в режиме «Авто» создаются две привязки: F0F (вперёд) и F0R (назад).
Один выход принимает несколько входящих Fx-связей и создаёт привязку на каждую F.
Прямая связь `Логика → Выход/Логический выход` переносит условие в
`func_binding_t`: поддерживаются до двух сравнений с числом, `AND`/`OR`,
инверсия ветки False и стандартные операторы `= != < <= > >=`. Сравнение с
другой переменной (`rhsVar`) и более двух условий в компактную привязку не
помещаются — редактор предупреждает и не создаёт такую привязку (fail closed).
Условие хранится в ранее неиспользуемых полях привязки (`short_table`,
`short_ms`, `min_ms`, `fade_ms`) и флагах `FUNC_FLAG_COND/COND2/COND_OR`, поэтому
размер NVS-записи и миграция не меняются. `func_eval_ex()` читает значения
переменных через `sound_variable_get()` из активного графа; старый `func_eval()`
остаётся обёрткой без условий.
Связь `Переменная/Задержка → Выход` условия не образует: это просто путь
выполнения, выход будет управляться F и гейтами `dir`/`state`.

### Блок «Двигатель»

Двигатель работает **всегда** (включается вместе с движением) и не имеет ни
F-клавиши, ни входного порта. В инспекторе остаются только громкость и
**количество ступеней**; проценты диапазонов распределяются поровну. Каждая
ступень — отдельный выходной порт (4 ступени — 4 порта с подписями диапазонов),
порт активен, пока скорость попадает в диапазон. Дополнительно у двигателя есть
выход **«Холостой ход»**, активный при нулевой скорости. К ступеням и к выходу
«Холостой ход» подключаются блоки `Звук` с выбранными звуковыми схемами;
внутренних WAV, полей Start/Idle/Stop и параметра Margin у блока больше нет.
Для непрерывного звука в диапазоне используйте схему с `Циклом`, для
одиночного срабатывания — с `Простым`. Схема на выходе «Холостой ход» обычно
состоит из `Старта` (завод двигателя) и `Цикла` (звук холостого хода): при
появлении скорости цикл останавливается, при возврате к нулю — запускается
снова.

### Блок «Старт» (звуковая схема)

У `Старта` нет собственного поля Trigger/F-клавиши. У блока есть **входной
порт** (связь может отсутствовать), поэтому схема может начинаться не со
`Старта`: например `Пауза → Старт → Цикл → Конец`. Триггер из Mixes
(связь `Вход (Fx)`/двигатель) применяется к **корневому блоку схемы** — блоку
без входящей связи; `Старт` получает управление по обычной связи от
предыдущего блока. В настройках `Старта` — звуковой файл, громкость и выход.

### Тип блока и имя

У блока можно менять имя; рядом с именем в шапке показывается тип блока, чтобы
после переименования было понятно, что это за блок.

### Прошивка

Формат графа расширен обратно совместимо (schema v1):

- `variables` — до `SG_MAX_VARIABLES = 16` переменных (встроенные + пользовательские);
- поля состояния `setVar`/`setValue` — присваивание при входе в состояние;
- условие `var_cmp` — `var`, `op` (0..5), значение либо `var2` (сравнение двух
  переменных).

Рантайм (`sound_graph_runner.c`) хранит значения пользовательских переменных,
вычисляет встроенные статусы на каждом такте и применяет `setVar` при входе.
Валидатор (`sound_graph.c`) проверяет имена/лимиты переменных, корректность
`var_cmp` и то, что `setVar` указывает на пользовательскую переменную. Схемы без
переменных (старые) парсятся как раньше. Покрыто `test_sound_graph`.

Компилятор редактора строит для блока «Логика» цепочку тихих состояний с
условиями `var_cmp` (AND — последовательно, OR — с ветвью «иначе»), а
`Переменная`/`Задержка` — тихие состояния с `setVar` и `timeout`.

## Аудит блоков (дубли и пробелы)

Убрано как дубли:
- `Световой эффект` — дублировал `AUX-выход` (световой эффект настраивается
  внутри AUX).
- `Короткий сигнал` — совпадал с `Тифон`; короткий/длинный уже даёт `Гудок`
  (режим «короткий/длинный»).

Оставлены как именованные пресеты с одинаковой логикой `oneshot`:
`Тифон`, `Сцепка`, `Песочница`, `Токоприёмник`, `Двери` — отличаются названием
и звуком, это удобные заготовки.

Реализовано:
- запуск по скорости и состоянию (`speed`) и по направлению (`dir_fwd`/`dir_rev`),
  тормоз по замедлению (`decel`), скоростные диапазоны в процентах (шаг 25 %,
  защита по умолчанию 5 %);
- случайный выбор звука (условие `random`);
- ducking двигателя под эффектами;
- повторное срабатывание завершённых цепочек (re-arm) и общий таймер цикла
  «По времени»;
- компактные условия `Логики` в привязках выходов/логических выходов
  (`func_eval_ex`, до двух сравнений, `AND`/`OR`, инверсия False);
- 18 одновременных эффектов (голоса 0..17; 18 — SELFTEST/HIL, 19 — двигатель) и
  повторный захват голоса при нехватке.

Прошивные изменения: `sound_graph.h` (условия и поля раннера),
`sound_graph_runner.c` (направление, ГПСЧ, выбор из random-группы),
`sound_graph.c` (парсер и валидация), `audio.c`/`audio.h`
(`audio_voice_set_volume_live`), `sound.c` (передача направления и ducking).
Покрыто host-тестами `test_sound_graph` (направление, random, разбор JSON) и
`test_audio` (аудио-компоненты с новым API).

## Как пользоваться

1. Открыть `/sound-editor/blocks.html` (или Настройки → «Миксы» /
   «Звуковые схемы»).
2. Добавить блоки из палитры слева; сетку при необходимости выключить.
3. Выбрать блок и заполнить справа: для `Входа (Fx)` — F-клавишу и режим; для
   остальных — WAV-файлы, канал/эффект, выход. Кнопка ▶ прослушивает звук.
   Список WAV — установленные на устройстве файлы (`/api/sound-files`).
4. Протянуть связи: от «выхода» одного блока к «входу» другого (со стрелкой).
   Любой звук/выход должен иметь цепочку от `Входа (Fx)`.
5. «▶ Тест блока» в инспекторе — проверка выбранного блока и его звука.
6. «Сохранить» (сохраняет и сразу применяет схему).

## Типовой проект локомотива

При первом открытии (и по команде **Файл → Типовой локомотив**) редактор
загружает готовый проект `locomotive_default`:

- `Двигатель` работает всегда, 4 ступени + выход «Холостой ход»; к каждой
  ступени подключён блок `Звук` со своей схемой `Двигатель 0–25/25–50/50–75/75–100%`
  (цикл notch, удерживается, пока скорость в диапазоне), а к выходу «Холостой
  ход» — схема `Холостой ход` (завод → цикл, останавливается при появлении
  скорости);
- **двенадцать именованных схем**: семь звуковых (гудок, звонок, компрессор,
  сцепка, песочница, двери открыть/закрыть), четыре схемы двигателя по
  ступеням и схема `Холостой ход` (завод `ms-start.WAV` → цикл `ms-loop.WAV`).
  В Mixes на них ссылаются блоки `Звук` (cue);
- схема `Гудок` с F2 (режим `hold`): `horn-low-init.wav` →
  `horn-low-loop.wav` (пока F2 удерживается) → `horn-low-exit.wav`;
- F3 — AUX1 (кабина), F4 — AUX2 (маяк), F11 — AUX3 (строб);
- F0 — фары (авто по направлению), F5 — звонок, F6 — компрессор,
  F7 — сцепка, F8 — песочница; F12/F13 — двери открыть/закрыть;
- F9/F10 — логические выходы «Набор/Сброс позиции»;
- F14 — логический пример: AUX4 «Вентилятор» включается только при
  `speed > 20` (условие переносится в привязку выхода);
- `Тормоз` работает как ambient-звук по замедлению.

`Двигатель` и ambient-`Тормоз` остаются блоками Mixes: двигатель управляется
скоростью и всегда активен, `Тормоз` — замедлением; они не могут быть схемой.
Все F-триггерные звуки вынесены в схемы, а звуки двигателя подключены к
выходам его ступеней блоками `Звук` (в типовом проекте — четыре схемы).

WAV-имена соответствуют типовому набору из папки `SOUND`. Если на устройстве
нет файла, сохранение покажет предупреждение/ошибку ассетов; после загрузки
звуков проект готов к применению. Команда **Новый** по-прежнему создаёт пустой
проект (только `Двигатель` и `Громкость`), чтобы шаблон не мешал ручной сборке.

```powershell
npm run build          # public\blocks.html -> dist\blocks.html
# или: node scripts\package-assets.mjs
# или: ..\build_sound_editor.ps1
```

Сборка не требует `npm install` и внешних пакетов — только Node.js (встроенные
модули). После правки обязательно пересобрать и закоммитить `dist/blocks.html`
и `dist/build-inputs.json` — иначе сборка прошивки отклонит устаревшие ассеты
(`build-inputs.json`).

## Актуальная семантика (0.12)

- **Повтор цепочки.** Завершённая цепочка возвращает канал эффекта во вход её
  корня; повторное нажатие F снова проигрывает цепочку от корня (например,
  `Пауза → Старт → ... → Конец`). Это
  работает и для цепочек через `Логику`/`Переменную`/`Задержку`, и для
  `Random`/`Компрессора`/`Звонка`.
- **Цикл «По времени»** считает время от входа в цикл; внутренний повтор
  короткого WAV не сбрасывает таймер.
- **Toggle/hold.** Для `toggle`-входа `Цикл/Звонок/Компрессор` завершаются
  повторным нажатием F (переход функции в `off`), для `hold` — отпусканием
  momentary-клавиши. `Короткое/длинное нажатие` по-прежнему различает тап и
  удержание по отпусканию.
- **Выходы и логика.** Прямая связь `Логика → Выход/Логический выход` несёт
  компактное условие (до двух сравнений, `AND`/`OR`, False-инверсия).
  `rhsVar` и более двух условий отклоняются с предупреждением.
- **Валидация.** WAV обязателен у `Старт/Простой/Цикл/Конец`, но `Старт` не
  обязателен: схема должна содержать хотя бы один блок (двигательные схемы —
  один `Цикл`). Пустой блок
  `Звук`, недостижимые состояния и превышение 32 эффектов
  диагностируются до сохранения. Пустые/сложные условия выходов дают
  предупреждение.
- **Голоса.** Двигатель использует голос 19; эффектам доступны голоса 0..17,
  голос 18 зарезервирован за SELFTEST/HIL.
  При нехватке голоса канал ждёт свободный голос и повторяет попытку.
- **Симулятор** подтягивает длительности WAV и показывает активные
  выходы/AUX и логические действия.

## Особенности текущей реализации

- **Глобальные обсерверы**: определены как **однократная оценка при запуске**.
  Блок `Логика`/`Переменная`/`Задержка` без входа выполняется на первом тике
  (`observers=true`), результат фиксируется; исходящие связи используют
  `state_enter` и срабатывают один раз. Для повторной оценки подключите вход:
  цепочка с входом re-arm возвращает канал в корень после завершения.
- **Обратная сборка**: граф без `editor.project` восстанавливается в Mixes
  best-effort компилятором `reverseGraphToProject` (Start/Simple/Loop/Mute/End,
  legacy-пресеты, speed/random/decel, engine, Logic/Var/Delay, Input-связи и
  цепочки). Состояния без редакторского эквивалента пропускаются с
  предупреждением; импорт выходов/AUX выполняется отдельно.
- **Предпросмотр** кнопкой ▶ теперь открывает **Симулятор** (условия, циклы,
  задержки, переменные, F/Engine), а не упрощённый проигрыватель файлов.
- **`min_ms`/`fade_ms`/`short_ms`** — исторические поля привязок
  `func_binding_t`. В графовом режиме для звуков они не используются, но
  `short_table`/`short_ms`/`min_ms`/`fade_ms` переиспользуются для компактных
  условий выходов/логики (см. раздел «Выход»).

## Ограничения движка (учитывать при добавлении блоков)

`SG_MAX_STATES 192` (не более `SG_MAX_SOUND_STATES 144` звучащих и
`SG_MAX_SILENT_STATES 96` тихих), `SG_MAX_TRANSITIONS 250`,
`SG_MAX_EFFECTS 32`, `SG_MAX_ASSETS 128`
(`firmware/components/sound/include/sound_graph.h`); привязок до
`FUNC_BIND_MAX 64` (`func_types.h`), одновременно звучат не более 19 эффектов.
Каждый блок расходует состояния/переходы, выходы — привязки. Редактор
показывает счётчики состояний/переходов/эффектов; превышение лимитов ловит
локальная и серверная валидация.
