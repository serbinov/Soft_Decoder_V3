# Конструктор звуковых блоков (sound blocks editor)

Простой редактор звуковой схемы из **готовых блоков тепловоза** — альтернатива
графовому редактору на Svelte. Страница написана на ванильном HTML/CSS/JS без
фреймворков и сборщиков поверх исходников: собирается тем же пайплайном, что и
основной редактор, и открывается по адресу `/sound-editor/blocks.html`.

- Исходник (правится): `firmware/sound_editor/public/blocks.html`
- Собранная копия (в git): `firmware/sound_editor/dist/blocks.html`
- Пункт в интерфейсе: «Настройки → Конструктор блоков (простой)»

## Что сделано

1. **Приложение редактора** — `firmware/sound_editor/public/blocks.html`.
   Самодостаточный файл: палитра, холст, инспектор, диагностика, тулбар.
2. **Библиотека готовых блоков** (12 типов):
   - Основные: `Двигатель`.
   - Сигналы: `Гудок`, `Тифон`, `Короткий сигнал`, `Звонок`.
   - Механика: `Компрессор`, `Тормоз`, `Сцепка`, `Песочница`, `Токоприёмник`, `Двери`.
   - Дополнительно: `Свой сценарий`.
3. **Компилятор блоков → схема устройства** (`sound-graph`, schema v1):
   каждый блок разворачивается в состояния/переходы; не-двигательные блоки
   получают тихий вход и `effect` с F-клавишей. ID, приоритеты, тихие входы,
   `immediate`/`after_sample` проставляются автоматически.
4. **Холст** — ванильный DOM + SVG: перетаскивание блоков мышью/пальцем,
   pan (тянуть фон), zoom (колесо), автоматическая раскладка при добавлении,
   позиции сохраняются в проекте. Связи рисуются SVG-путями.
5. **Связи между блоками**: связь «Двигатель → блок» переводит блок в режим
   «При двигателе» (условия `engine_on`/`engine_off` вместо F-клавиши).
   Остальные связи — организационные (см. «Что надо будет сделать»).
6. **Инспектор**: название, F-клавиша, громкость, режим запуска, WAV-файлы по
   ролям (начало/цикл/конец/короткий/звук), ступени скорости двигателя.
   Выпадающий список WAV берётся из `/api/audio/tracks`.
7. **Проверка**: клиентская (лимиты, тихие входы, уникальные приоритеты,
   ссылки) + серверная `/api/sound/graph/validate`; отсутствующие WAV —
   предупреждение.
8. **Сохранение/применение**: `POST /api/sound/graph/save` и
   `POST /api/sound/graph/apply` с манифестом WAV из `/api/sound/graph/asset`.
9. **Локальное восстановление**: черновик в `localStorage`;
   экспорт/импорт JSON проекта блоков (`*.blocks.json`).
10. **Раздача без правок C-кода**: `public/` копируется Vite в `dist/`, а
    существующий `sound_editor_get` в `web.c` уже отдаёт любой файл под
    `/sound-editor/`. Прошивка и превью отдают страницу без изменений в web.c.
11. **Проверка свежести сборки**: `public/` добавлен в хэш
    `package-assets.mjs` и в `gen_sound_editor.py` (`verify_sources`), чтобы
    правка исходника без пересборки отклонялась на этапе сборки прошивки.
12. **Пункт меню**: добавлена отдельная панель в `firmware/web_ui.html`
    (Настройки → «Конструктор блоков (простой)»).

## Как пользоваться

1. Открыть `/sound-editor/blocks.html` (или Настройки → «Конструктор блоков»).
2. Добавить нужные блоки из палитры слева.
3. Выбрать блок и заполнить справа: F-клавишу и WAV-файлы.
4. При необходимости протянуть связь от «Двигателя» к блоку (режим «При двигателе»).
5. «Проверить» → «Сохранить» → «Применить» (двигатель должен быть остановлен).

## Как менять исходник

```powershell
cd firmware\sound_editor
npm run build          # public\blocks.html -> dist\blocks.html
```

После правки `public/blocks.html` обязательно пересобрать и закоммитить
обновлённый `dist/blocks.html`, иначе сборка прошивки отклонит устаревшие
ассеты (`build-inputs.json`).

## Что надо будет сделать

- **Семантические связи между блоками** (сейчас только «Двигатель → блок»):
  «запустить Y после завершения X», задержки, «глушить двигатель при эффекте».
- **Блоки выходов и логики**: Свет (`F0F/F0R`), `AUX1..7`, логические операции
  (`MUTE_*`, `DRIVE_HOLD`, `COAST`, `DYNAMIC_BRAKE`, `NOTCH_UP/DOWN`). Требуют
  записи `func_binding_t` через `/api/func-map?bind=1` — согласовать
  добавление/удаление привязок, чтобы не затирать пользовательские.
- **Расширенные параметры блока**: `rate`, `min_ms`, `fade_ms`, порог короткого
  нажатия `short_ms`, интервал для «Звонка», порог `decel` для «Тормоза».
- **Режим `state` и `random`** для тормоза/звонка (сейчас упрощены до
  `latched`/`oneshot`).
- **Двигатель**: отдельные WAV на ступени уже есть; добавить настройку
  включения/выключения без файла `start`/`stop`, гистерезис, привязку к
  реальным функциям набора позиций.
- **Круговая загрузка блока-слоя с устройства**: сейчас устройство хранит
  только скомпилированную схему v1, поэтому блоки восстанавливаются из
  локального черновика или импорта. Нужен либо отдельный слот хранения
  блока-проекта, либо обратная сборка блоков из состояний/переходов.
- **Отмена/повтор (undo/redo)** на холсте.
- **Мобильная раскладка** (палитра/инспектор как выдвижные панели) и
  корректные жесты масштабирования.
- **Связь с существующими привязками F-клавиш**: показывать занятые функции и
  предупреждать о конфликтах с уже настроенными привязками.
- **Тесты**: unit для компилятора (по образцу `sound_editor/test/model.test.mjs`)
  и e2e Playwright (добавить блок, связать, проверить, сохранить).
- **Решить судьбу Svelte-редактора**: после паритета по возможностям перенести
  расширенные функции в блочный редактор и убрать зависимость Svelte/xyflow.

## Ограничения движка (учитывать при добавлении блоков)

`SG_MAX_STATES 57`, `SG_MAX_TRANSITIONS 128`, `SG_MAX_EFFECTS 24`
(`firmware/components/sound/include/sound_graph.h`). Каждый блок расходует
несколько состояний и переходов; редактор показывает остаток бюджета.
