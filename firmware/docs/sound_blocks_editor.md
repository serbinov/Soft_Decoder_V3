# Конструктор звуковых блоков (sound blocks editor)

Простой редактор звуковой схемы тепловоза из **готовых блоков** — альтернатива
графовому редактору на Svelte. Страница написана на ванильном HTML/CSS/JS без
фреймворков; собирается тем же пайплайном, что и основной редактор, и
открывается по адресу `/sound-editor/blocks.html`.

- Исходник (правится): `firmware/sound_editor/public/blocks.html`
- Собранная копия (в git): `firmware/sound_editor/dist/blocks.html`
- Пункт в интерфейсе: Настройки → «Конструктор блоков (простой)»

## Что сделано

1. **Приложение редактора** — `firmware/sound_editor/public/blocks.html`:
   палитра, холст, инспектор, диагностика, тулбар. Без внешних зависимостей.
2. **Библиотека готовых блоков** (21 тип, 5 групп):
   - Основные: `Двигатель`.
   - Сигналы: `Гудок`, `Тифон`, `Короткий сигнал`, `Звонок`.
   - Механика: `Компрессор`, `Тормоз`, `Сцепка`, `Песочница`, `Токоприёмник`, `Двери`.
   - Свет и выходы: `Фары`, `AUX-выход`, `Логика`.
   - Освещение (AUX): `Лампа накаливания`, `Марс/прожектор`, `Ходовые огни`,
     `Маяк`, `Строб`, `Топка`.
   - Дополнительно: `Свой сценарий`.
3. **Компилятор звуковых блоков → схема устройства** (`sound-graph`, schema v1):
   состояния/переходы, тихие входы, `effects`, приоритеты, `immediate`/
   `after_sample` проставляются автоматически.
4. **Компилятор блоков выходов/логики → привязки** `func_binding_t`:
   - `Фары` → `FUNC_TARGET_OUTPUT` id 0 (F0F, dir=вперёд) и/или id 1 (F0R, dir=назад)
     в зависимости от направления (`Авто/вперёд/назад/без направления`);
   - `AUX-выход` и блоки освещения → `FUNC_TARGET_OUTPUT` id 2..8 (AUX1..7);
   - `Логика` → `FUNC_TARGET_LOGIC` (mute стоп/ход/свет, удержание хода,
     выбег, дин. тормоз, набор/сброс позиции);
   - уровень и эффект AUX пишутся в `/api/aux/cfg`
     (постоянный, лампа накаливания, Марс, ходовые, маяк, строб, топка).
5. **Холст**:
   - перетаскивание блоков мышью/пальцем, pan (тянуть фон), zoom (колесо);
   - **привязка к сетке** (тумблер «Сетка») и кнопка **«Выровнять»**
     (слоёная авто-раскладка по связям);
   - **соединение мышью с живым предпросмотром**: во время протяжки рисуется
     пунктирная линия, на конце — **стрелочка** (SVG marker);
   - **метки входа и выхода** на каждом блоке и цветные порты
     (синий — вход, зелёный — выход);
   - клик по связи удаляет её.
6. **Инспектор**: зависит от типа блока — F-клавиша, громкость/яркость, режим
   запуска, WAV по ролям, ступени скорости, направление фар, AUX-канал,
   эффект освещения, логическая операция. Список WAV — из `/api/audio/tracks`.
7. **Связи**:
   - `Двигатель → звуковой блок` включает режим «При двигателе»
     (`engine_on`/`engine_off` вместо F-клавиши);
   - `звуковой блок → блок выхода/логики` передаёт блоку F-клавишу источника
     (маршрутизация привязки на тот же F);
   - прочие связи — организационные (см. «Что надо будет сделать»).
8. **Проверка**: клиентская (лимиты, тихие входы, приоритеты, ссылки, каналы)
   + серверная `/api/sound/graph/validate`; отсутствующие WAV — предупреждение.
9. **Запись/применение**:
   - «Сохранить» — граф (`/api/sound/graph/save`);
   - «Выходы» — привязки (`/api/func-map?bind=1`) и AUX-эффекты (`/api/aux/cfg`);
   - «Применить» — сохранённый граф + запись выходов.
   Привязки, созданные редактором, отслеживаются и удаляются при изменении
   схемы; чужие привязки не трогаются.
10. **Локальный черновик** в `localStorage`; экспорт/импорт JSON (`*.blocks.json`).
11. **Раздача без правок C-кода**: `public/` копируется Vite в `dist/`,
    существующий `sound_editor_get` отдаёт файл. `public/` включён в проверку
    свежести сборки (`package-assets.mjs` и `gen_sound_editor.py`).
12. **Пункт меню**: отдельная панель в `firmware/web_ui.html`.

## Как пользоваться

1. Открыть `/sound-editor/blocks.html` (или Настройки → «Конструктор блоков»).
2. Добавить блоки из палитры слева; сетку при необходимости выключить.
3. Выбрать блок и заполнить справа: F-клавишу, WAV-файлы, канал/эффект.
4. Протянуть связи: от «выхода» одного блока к «входу» другого (со стрелкой).
5. «Выровнять» — аккуратная раскладка по связям.
6. «Проверить» → «Сохранить» → «Выходы» (или сразу «Применить»).

## Как менять исходник

```powershell
cd firmware\sound_editor
npm run build          # public\blocks.html -> dist\blocks.html
```

После правки обязательно пересобрать и закоммитить `dist/blocks.html` —
иначе сборка прошивки отклонит устаревшие ассеты (`build-inputs.json`).

## Что надо будет сделать

- **Семантические связи** между блоками помимо описанных: «запустить Y после
  завершения X», задержки, «глушить двигатель при эффекте» (ducking),
  направление/состояние как условия связи.
- **Круговое чтение привязок с устройства** при открытии (сейчас редактор
  отслеживает только созданные им привязки и не подгружает существующие
  как блоки).
- **Обратная сборка блоков из схемы устройства** (сейчас устройство хранит
  только скомпилированную схему v1; блоки восстанавливаются из локального
  черновика или импорта).
- **Расширенные параметры**: `min_ms`, `fade_ms`, `short_ms`, интервал для
  «Звонка», порог `decel` для «Тормоза», ручной период AUX-эффекта.
- **Режимы `state`/`random`** для тормоза/звонка (сейчас `latched`/`oneshot`).
- **Отмена/повтор (undo/redo)**, мультивыделение и копирование блоков.
- **Мобильная раскладка** (выдвижные палитра/инспектор), тач-жесты масштаба.
- **Предупреждения о конфликтах** с уже занятыми F-клавишами и привязками.
- **Тесты**: unit для компилятора (по образцу `sound_editor/test/model.test.mjs`)
  и e2e Playwright (добавить блок, связать, выровнять, записать выходы).
- **Решение о судьбе Svelte-редактора** после функционального паритета.

## Ограничения движка (учитывать при добавлении блоков)

`SG_MAX_STATES 57`, `SG_MAX_TRANSITIONS 128`, `SG_MAX_EFFECTS 24`
(`firmware/components/sound/include/sound_graph.h`); привязок до
`FUNC_BIND_MAX 64` (`func_types.h`). Каждый блок расходует состояния/переходы
и, для выходов, привязки; редактор показывает остаток бюджета.
