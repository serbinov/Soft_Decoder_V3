# AURA Sound Pack (`.asp`) — формат контейнера

Контейнер для пакетной загрузки звуков в декодер. Один `.asp`-файл несёт до
**400** звуков; прошивка стримит его прямо из тела HTTP-запроса и распаковывает
в отдельные `*.wav` в `/userdata/audio/`, поэтому старые звуки сначала
удаляются, а копия всего пакета на плате не хранится.

Версия формата: **1**. Код: `components/web/include/audio_pack.h`,
`components/web/src/audio_pack.c`. Упаковщик: `tools/pack_sounds.py`.

## Зачем

- Мало служебных байт: заголовок 16 Б + компактный индекс, данные — **IMA ADPCM**
  (по умолчанию, ~4× меньше) или PCM16.
- Не требует распаковщика ZIP и не увеличивает файл: вместо 400 отдельных
  файлов LittleFS — один поток.
- Готовится на компьютере: `python tools/pack_sounds.py SRC_DIR -o pack.asp`.

## Кодирование звука

По умолчанию звук хранится как **IMA ADPCM** (MS `WAVE_FORMAT_IMA_ADPCM`, монo,
блок 256 Б = 505 сэмплов): декодер на устройстве простой (несколько сложений и
таблица шага) и не вызывает заиканий даже при многих одновременных голосах, а
объём падает примерно в 4 раза. Флаг `--pcm` отключает сжатие (PCM16).

Устройство выводит звук как моно 22050 Гц PCM16, поэтому упаковщик:

- сводит все входные WAV в моно;
- **понижает** частоту до потолка `--rate` (по умолчанию 22050 Гц); файлы с
  меньшей частотой не пересэмплируются вверх (это только раздуло бы размер —
  микшер всё равно приводит всё к 22050);
- кодирует в ADPCM (или PCM16 с `--pcm`);
- поддерживает вход PCM 8/16/24/32 бита и IEEE float32, WAVE_FORMAT_EXTENSIBLE.

## Раскладка (little-endian)

```
Заголовок (16 Б):
  0x00  char[8]  magic = "AURASP01"
  0x08  u16      version = 1
  0x0A  u16      count   = 1..400
  0x0C  u32      data_off — абсолютное смещение первого payload

Индекс (count записей, подряд):
  u8    name_len   (1..63; базовое имя без ".wav")
  u8    volume     (0..100; пофайловая громкость по умолчанию)
  u8    channels   (1..2; ADPCM — только 1)
  u8    bits       (16 = PCM16, 4 = IMA ADPCM)
  u32   sample_rate
  u32   data_off   (абсолютное; записи идут подряд)
  u32   data_len   (PCM16: байт, кратно channels*2; ADPCM: кратно 256)
  char  name[name_len]     (UTF-8)

Payload: PCM16 или ADPCM-блоки подряд по data_off, последний заканчивается
ровно в конце файла. На распаковке устройство пишет для ADPCM стандартный
WAV-заголовок (60 Б: fmt 20 Б + fact) и блоки ADPCM.
```

Индекс заканчивается ровно на `data_off`; payload-и идут без промежутков, что
позволяет распаковывать их последовательно из потока без fseek.

## Ограничения

- `count` ≤ 400 (`AUDIO_PACK_MAX_FILES`), `name` ≤ 63 байт UTF-8.
- Тело запроса ≤ 15 МБ (`AUDIO_PACK_MAX_BYTES`); дополнительно проверяется
  свободное место: `total_payload + count·4 КиБ + 256 КиБ` (с учётом места,
  которое освободит удаление старой библиотеки).
- Имена санитизируются как `sanitize_name` (ASCII `[A-Za-z0-9_.-]` и байты
  ≥ 0x80; остальные → `_`), расширение `.wav` добавляет плата.
- Дубликаты имён после санитизации — ошибка 400.

## Протокол

- `GET /api/audio/library` → `{ok, count, preview, files:[{name,size,vol}]}` — список
  установленных звуков (имя, размер `.wav` в байтах, пофайловая громкость);
  `preview` — имя играющего сейчас.
- `POST /api/audio/pack` — тело `.asp`; **удаляет всю старую библиотеку** и
  распаковывает новую. Ответ `{ok, files, bytes}`. Идёт через `web_transfer`
  (асинхронно), прогресс на порту 81 `/progress`.
- `POST /api/audio/play?name=NAME` — предпрослушивание файла с его пофайловой
  громкостью (плюс общая громкость).
- `POST /api/audio/library/volume?name=NAME&vol=0..100` — задать громкость файла
  (сайдкар `/userdata/audio/volumes.txt`, формат `AURAVOL1` + строки `vol<TAB>name`).
- `GET /api/sound-files` — `{"files":["имя.wav", …]}` для конструктора блоков.
- `GET /sound-files/<имя>` — **воспроизведение на компьютере**: браузеру отдаётся
  PCM16-WAV (ADPCM декодируется на лету), поэтому звук играет в браузере.

Воспроизведение (превью библиотеки и конструктор блоков) по умолчанию идёт в
**браузере компьютера**; переключатель «Воспроизведение: На компьютере / На
декодере» на странице «Загрузка звуков» хранится в localStorage
(`aura_sound_play`, по умолчанию `pc`) и общий для основной страницы и редактора.

Старый пофайловый аплоад `POST /api/audio/upload` и удаление
`POST /api/audio/delete` оставлены для совместимости, но в вебе больше не
используются.

## Пример

```powershell
python tools/pack_sounds.py ..\..\SOUND -o SOUND.asp
# -> Packed 17 file(s), 2429113 B -> SOUND.asp
```

Затем на странице «Загрузка звуков» → **Загрузить звуковой пакет**.

> Загрузка пакета полностью заменяет библиотеку звуков. Активная звуковая
> схема (граф) ссылается на файлы по имени: после замены нужные ассеты должны
> присутствовать в новом пакете, иначе воспроизведение таких состояний
> завершится ошибкой (движок fail-closed).
