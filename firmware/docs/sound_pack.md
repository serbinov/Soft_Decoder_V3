# AURA Sound Pack (`.asp`) — архитектура упаковки/распаковки звуков и звуковой схемы

Контейнер `.asp` объединяет **аудиофайлы (`*.wav`)**, **пофайловую громкость (`volumes.txt`)** и **звуковую схему (`scheme.json` / `sound-graph`)** в один файл.
При загрузке `.asp` в декодер (`POST /api/audio/pack`) устройство в рамках одной транзакции распаковывает звуки в `/userdata/audio/*.wav`, проверяет, сохраняет и сразу активирует встроенную звуковую схему.

Версия формата: **1**.
Код прошивки: `components/web/include/audio_pack.h`, `components/web/src/audio_pack.c`, `components/web/src/web.c`.
Утилита упаковки/распаковки: `tools/pack_sounds.py`.

---

## 1. Бинарная раскладка контейнера `.asp` (little-endian)

```
Заголовок (16 Б):
  0x00  char[8]  magic = "AURASP01"
  0x08  u16      version = 1
  0x0A  u16      count   = 1..400 (общее число записей в индексе)
  0x0C  u32      data_off — абсолютное смещение первого payload-блока

Индекс (count записей, подряд без выравнивания):
  u8    name_len   (1..63; базовое имя файла без ".wav" или "__aura_scheme__")
  u8    volume     (0..100; для записи схемы = 0)
  u8    channels   (1..2 для PCM16, 1 для ADPCM, 0 для записи схемы)
  u8    bits       (16 = PCM16, 4 = IMA ADPCM, 0 = встроенная звуковая схема JSON)
  u32   sample_rate (Гц для аудио; 0 для записи схемы)
  u32   data_off   (абсолютное смещение payload; записи идут строго подряд)
  u32   data_len   (размер payload в байтах)
  char  name[name_len] (UTF-8)

Данные (Payloads):
  Идут сразу после индекса с позиции `data_off` в том же порядке, что и записи индекса:
  - для `bits = 4` (IMA ADPCM): блоки по 256 байт (505 сэмплов на блок);
  - для `bits = 16` (PCM16): сырые сэмплы int16 LE;
  - для `bits = 0` (`name = "__aura_scheme__"`): UTF-8 JSON скомпилированного графа (`format: "sound-graph"`), до 128 КиБ.
```

## 2. Упаковка и распаковка (`tools/pack_sounds.py`)

### 2.1. Упаковка папки со звуками и схемой в `.asp`

```powershell
# Автоматически подхватывает scheme.json / sound_graph.json / project.json из папки SRC_DIR, если он там есть:
python firmware/tools/pack_sounds.py SOUND -o ChME3.asp

# Или с явным указанием файла звуковой схемы:
python firmware/tools/pack_sounds.py SOUND --scheme my_scheme.json -o ChME3.asp
```

**Что делает упаковщик `pack_sounds.py` при сборке `.asp`:**
1. Читает все `.wav` из папки, приводит их к моно (или стерео с `--pcm --stereo`), понижает частоту дискретизации до `--rate` (по умолчанию `22050 Гц`) и кодирует в **IMA ADPCM** (или PCM16 с `--pcm`).
2. Для каждого упакованного WAV-файла вычисляет **точный манифест ассета** (`size`, `sampleRate`, `channels`, `bits`, `durationMs`, `crc32`), полностью идентичный тому файлу, который прошивка запишет на флеш-память при распаковке.
3. Если передан `--scheme` (или в папке лежит `scheme.json`), читает JSON звуковой схемы, проверяет, что все используемые в состояниях `states[].file` звуки присутствуют в пакете, автоматически заполняет массив `assets[]` актуальными `crc32`/`size`/`durationMs` и добавляет запись `__aura_scheme__` (`bits=0`) в индекс `.asp`.

### 2.2. Распаковка `.asp` обратно в папку (звуки + `volumes.txt` + `scheme.json`)

```powershell
python firmware/tools/pack_sounds.py ChME3.asp --unpack -o unpacked_dir
```

При распаковке создаются:
- все файлы `*.wav` со стандартными RIFF/WAVE заголовками;
- файл `volumes.txt` с индивидуальными уровнями громкости (`имя=громкость`);
- файл `scheme.json` (отформатированный с отступами), если в пакет была вложена звуковая схема.

### 2.3. Как получить `scheme.json` из визуального Конструктора Блок Схем

В веб-интерфейсе конструктора (`/sound-editor/blocks.html`):
1. Соберите или отредактируйте схему в режимах **«Миксы»** и **«Звуковые схемы»**.
2. Откройте меню **«Файл → Экспорт схемы для пакета (.json)»**.
3. Сохраните полученный `scheme.json` в папку с `.wav`-файлами и запустите `pack_sounds.py`.

### Экспорт из веб-интерфейса

«Настройки → Экспорт звукового пакета» собирает `.asp` из всей библиотеки звуков:
- в пакет попадают все `.wav` библиотеки, включая неиспользуемые схемой;
- встроенная схема сохраняется вместе с манифестом только тех файлов, на которые ссылаются её состояния;
- PCM16 и 8-битный PCM сжимаются в моно IMA ADPCM; 8-битный PCM предварительно расширяется до 16 бит;
- перед скачиванием показывается статистика (звуки, размер, форматы, частота, схема, процент сжатия);
- пакет больше 15 МБ сохраняется, но помечается как неимпортируемый на декодер.

## 3. Процесс распаковки на устройстве (`POST /api/audio/pack`)

Когда пользователь загружает `.asp` через веб-интерфейс («Настройки → Импорт звукового пакета»):
1. **Чтение заголовка и индекса:** проверяются `AURASP01`, размеры и непрерывность смещений.
2. **Проверка ссылок:** встроенная схема (`__aura_scheme__`) не блокирует замену собственных звуков, но файлы, на которые ссылаются другие сохранённые проекты, по-прежнему защищены от удаления.
3. **Staging во временные файлы:** все новые `.wav` потоково записываются во временные файлы и проверяются через `audio_inspect_wav()`; встроенная схема парсится и валидируется через `sg_parse()` и `sg_validate()`.
4. **Атомарная замена библиотеки:** старые `.wav` переносятся во временный backup-каталог, новые публикуются в `/userdata/audio/*.wav`. При любом сбое до коммита старые файлы восстанавливаются из backup.
5. **Автоматическое сохранение и активация звуковой схемы (часть транзакции):**
   - прошивка проверяет манифест `sg_assets_validate()` по только что распакованным WAV-файлам;
   - сохраняет новую ревизию схемы в хранилище графов (`sg_store_save_force()`);
   - подготавливает и активирует схему в рантайме (`sound_graph_prepare()` → `sg_store_select()` → `sound_graph_commit()`);
   - при ошибке на любом из этих шагов импорт откатывается вместе со звуками, а старый backup ещё не удалён;
   - возвращает JSON `{"ok":true,"files":N,"bytes":B,"scheme":"<id>","revision":R}`.
6. **Громкости** сохраняются после активации схемы; сбой записи `volumes.txt` не откатывает уже применённый импорт и оставляет громкость по умолчанию (100).
7. Веб-интерфейс сбрасывает старый локальный черновик `localStorage`, чтобы при открытии «Конструктора Блок Схем» автоматически загрузилась новая схема из пакета.
