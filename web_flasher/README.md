# ADDITIPUS — панель прошивки (веб)

Веб-страница — **настройка, статус, запуск и статистика**. Саму прошивку выполняют
**скрипты** проекта (`firmware\flash_esptool.ps1`, `web_flasher\flash_with_sound_pack.ps1`) —
те же, что и при ручном запуске, поэтому используется проверенный на железе
механизм входа в режим загрузчика.

## Быстрый запуск

1. Соберите **`build_firmware.bat`** в корне проекта **или** нажмите
   **«Собрать прошивку»** прямо в панели. Он публикует и проверяет
   `release\flash_download_tool\` (4 файла) и единый versioned BIN в `release\`.
2. Запустите **`web_flasher\start_flasher.bat`** (двойной клик). Он поднимает
   локальный сервер на встроенном PowerShell (**ничего устанавливать не нужно**)
   и открывает браузер.
3. В панели посмотрите блок **«Состояние»** и нажмите нужное действие.

Сервер **завершается сам**, когда закрыты все вкладки страницы (через ~12 с) —
порт освобождается, и повторный запуск не падает с «порт занят».

## Шесть действий

| Кнопка | Что делает | Скрипт |
|---|---|---|
| **Собрать прошивку** | собирает BIN из исходников и публикует `release\flash_download_tool\` (нужен ESP-IDF) | `build_firmware.bat` |
| **Создать звуковой контейнер** | собирает `release\ADDITIPUS_sounds.asp` из папки `SOUND\` (до 400 звуков) для загрузки на странице «Загрузка звуков» декодера (нужен Python 3) | `make_sound_pack.ps1` |
| **Прошить** | прошивка по USB: загрузчик + разделы + приложение; настройки/NVS сохраняются | `flash_esptool.ps1` (esptool) |
| **Прошить + полный пакет звуков** | собирает `.asp` из `SOUND\` (до 400 звуков), прошивает firmware и передаёт пакет по USB/COM кадрами 32 КБ (`PACK-DATA`) — без Wi-Fi и без PUT на каждый звук | `flash_with_sound_pack.ps1` |
| **Прошить + звуки схемы** | собирает `release\ADDITIPUS_scheme_sounds.asp` только из звуков типового проекта «Тепловоз ЧМЭ3» (`firmware\sound_editor\default_scheme_sounds.txt`), прошивает и заливает по COM; лишние звуки из `SOUND\` не попадают | `flash_with_sound_pack.ps1 -DefaultScheme` |
| **Стереть всё (заводской сброс)** | полностью стирает внутреннюю flash (прошивка, NVS, CV, настройки, калибровки), заново прошивает релиз и форматирует внешнюю NOR (звуки, схемы, служебные файлы). Необратимо | `factory_reset.ps1` |

Кнопка **«Стереть всё»** требует отдельного подтверждения. Внутренняя flash
стирается через `flash_esptool.ps1 -Erase` (или ROM-fallback
`flash_standalone.ps1 -Erase`), затем прошивается релиз и по COM отправляется
команда `WIPE`, которая форматирует внешнюю NOR. После завершения декодер
находится в заводском состоянии.

Кнопка **«Прошить + полный пакет звуков»** заменяет звуковую библиотеку на
устройстве целиком. Кнопка **«Прошить + звуки схемы»** загружает только звуки,
на которые ссылается встроенный типовой проект; список ведётся в
`firmware\sound_editor\default_scheme_sounds.txt` и проверяется тестом
`test_blocks_editor.js`. Если пакет уже собран, его можно залить вручную на
странице декодера «Загрузка звуков».

Схема при этом отдельно не заливается: типовой проект «Тепловоз ЧМЭ3» встроен
в прошивку (`firmware\main\data\default_scheme.json`) и устанавливается
устройством при загрузке, если никакая схема ещё не выбрана. После этого
любая сохранённая в редакторе версия имеет приоритет — при следующей загрузке
декодер берёт последнее сохранение, а не встроенный вариант. Если сохранены
звуки, но проект ещё не установился (например, пакет не был залит), загрузка
остаётся тихой и повторяет установку при следующем включении.

Папка звуков ищется сначала в `<репозиторий>\SOUND` (`Soft_Decoder_V3\SOUND`),
затем рядом с репозиторием (`..\..\SOUND`).

### Звуки: PROV (до 20) или контейнер (до 400)

- **Прошить + полный пакет звуков** собирает `.asp` (реальные имена, до 400
  звуков, **IMA ADPCM ~4×**, моно), прошивает firmware и передаёт пакет по
  USB/COM кадрами по 32 КБ (`PACK-DATA`); подтверждение идёт на кадр, а не на
  каждый звук или 4 КБ. Устройство само распаковывает его в `/userdata/audio`;
  Wi-Fi не нужен. Текущая библиотека на устройстве заменяется.
- **Прошить + звуки схемы** собирает фильтрованный `.asp`
  (`release\ADDITIPUS_scheme_sounds.asp`) только из звуков типового проекта и
  заливает его тем же COM-путём. Перечень ведётся в
  `firmware\sound_editor\default_scheme_sounds.txt`; упаковщик выбирает файлы по
  санитизированным именам, поэтому `#`, пробелы и умлауты в `SOUND\` не мешают.
- **Создать звуковой контейнер** только собирает тот же `.asp` в
  `release\ADDITIPUS_sounds.asp`; его можно загрузить через веб-интерфейс
  декодера кнопкой **«Загрузить звуковой пакет»**. Формат —
  `firmware/docs/sound_pack.md`.
- **PROV (до 20 звуков)** остаётся ручным путём: `flash_esptool.ps1 -Sounds`
  заливает WAV по UART (слоты 1..20, файлы до 4 МиБ). Для больших библиотек
  используйте полный пакет.

Прошивка идёт через **esptool** — он сам проверяет записанное
(`Hash of data verified`), поэтому это надёжный путь. Панель ищет esptool так:

1. автономный **`firmware\tools\esptool\esptool.exe`** — уже лежит в проекте
   (официальная standalone-сборка **esptool v5.4.0**, ~15 МБ, **без установки и без Python**);
2. иначе — esptool из установленного ESP-IDF (`python -m esptool`);
3. если ничего нет — автономный `flash_standalone.ps1` (чистый PowerShell).

Для переноса на другую машину достаточно скопировать проект целиком (включая
`firmware\tools\esptool\esptool.exe`) — ни Python, ни ESP-IDF не нужны.

## Вкладки

- **Прошивка** — состояние, три действия и **цветной лог**: `[INFO]` синий,
  `[OK]` и `Hash of data verified` зелёные, `[WARN]` жёлтый, `[ERROR]`/`ошибка`
  красные, проценты записи — серые.
- **Статистика** — сводка (**всего / успешно / ошибок / последняя**) и **история
  прошивок**: дата, действие, порт, **MAC чипа**, результат, версия, размер,
  число звуков, длительность, метод (esptool vX). История хранится в файле
  **`web_flasher\stats.json`** (до 500 записей) и видна при следующем открытии.
  MAC берётся из USB-серийника ESP32-S3 (без входа в режим загрузчика).

Вывод скрипта идёт в лог **в реальном времени**: порт, вход в режим загрузчика,
запись с прогрессом, проверка хеша, перезагрузка, код завершения.

## Состояние (блок «Состояние»)

Панель показывает: **порт платы** (авто-определение по USB VID_303A/PID_1001),
найден ли **ESP-IDF** (для прошивки не требуется), сколько **файлов прошивки**
и **звуков** найдено. Готовность требует всех четырёх BIN, актуального
`release\manifest.json` и совпадения размеров/SHA256, версии и адресов.
Один случайный `.bin` больше не считается готовой прошивкой.

| Файл | Адрес | Формат |
|---|---|---|
| `flash_download_tool\bootloader.bin` | `0x0` | ESP32-S3 bootloader |
| `flash_download_tool\partitions.bin` | `0x8000` | Partition table с MD5 |
| `flash_download_tool\ota_data_initial.bin` | `0x1a000` | 8192 erased bytes |
| `flash_download_tool\firmware.bin` | `0x20000` | Raw ESP32-S3 application |

`ADDITIPUS_AURA-X_v<ver>.bin` — единственная копия raw application (не merged
full-flash image) и одновременно файл для обновления через веб-интерфейс декодера.
Отдельного `_OTA.bin` больше нет. Не заменять `firmware.bin` merged-образом.
Исторические versioned файлы не выбираются USB-прошивальщиком автоматически.

Полная офлайн-проверка release (Python, без платы):
```powershell
python firmware\tools\release_artifacts.py verify --release release
python -B firmware\test\test_release_artifacts.py
```
ESP images проверяются по chip ID, сегментам, checksum и appended SHA256;
partition binary сравнивается с CSV/планом сборки и проверяется по MD5.
Пакеты `AURAOTA2`, если присутствуют, разбираются полностью с ограничениями
декодера: максимум 20 PCM16 WAV, 2 МиБ/файл и 8 МиБ/контейнер, без trailing bytes.

## Требования

- Windows 10/11 — встроенный PowerShell, без установки. Можно использовать на
  чистой машине: только Chrome/Edge + USB-кабель.
- Chrome / Edge для страницы.

## Почему веб только для настройки

Браузерный Web Serial не на всех машинах надёжно уводит ESP32-S3 в режим
загрузчика. Скрипты делают это так же, как esptool, и проверены на реальной плате,
поэтому прошивка идёт через них, а веб оставлен для удобной настройки, запуска и
показа лога.

## Устранение неполадок

- **Порт не найден** — подключите USB и нажмите «Обновить»; при необходимости
  зажмите **BOOT** и коротко нажмите **RST**.
- **Нет/повреждены/устарели BIN** — соберите `build_firmware.bat`; не переименовывать
  старый образ в новую версию. Версия берётся только из проверенного manifest.
- **Страница без сервера** — запускайте через `start_flasher.bat`, а не двойным
  кликом по `index.html` (тогда нет доступа к скриптам и статусу).
- **Полный пакет: нет `PACK-READY`** — прошейте firmware с поддержкой `PACK`
  (текущий release) и проверьте, что COM-порт не занят другим терминалом.
- **Не собирается `.asp`** — нужен Python 3 (`python`, `py -3` или Python из
  ESP-IDF); панель находит его автоматически.
